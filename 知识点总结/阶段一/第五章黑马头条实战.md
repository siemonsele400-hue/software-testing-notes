# 阶段一：测试基础

## 第五章：黑马头条实战

本章以黑马头条 Web 项目为案例，把前面学习的测试基础、需求分析、测试点提取、测试用例、缺陷管理和测试报告串成一个完整的功能测试流程。

本章的核心不是单纯记住“登录”和“发布文章”的操作，而是学会：

1. 从需求和原型中识别可测试的规则；
2. 按正常、异常、边界、兼容性等维度提取测试点；
3. 使用统一模板编写可执行测试用例；
4. 执行用例并记录实际结果和证据；
5. 使用规范格式提交缺陷；
6. 根据执行结果输出测试总结和风险结论。

# 一、项目概览

## 5-1 项目定位

黑马头条是一款汇集科技资讯、技术文章和问答交流的产品，用户可以查看资讯、发表或学习技术文章，并参与技术问题讨论。

项目主要包含三个前端子产品：

| 子产品 | 主要使用者 | 主要功能 |
| --- | --- | --- |
| 用户端 App | 普通用户 | 查看资讯、阅读文章、问答和交流 |
| 自媒体运营平台 | 自媒体用户 | 管理文章、评论和粉丝数据 |
| 系统后台 | 内部运营人员 | 管理内容、用户和平台运营数据 |

本章重点测试的是自媒体运营平台的 Web 功能，主要范围包括：

- 登录功能；
- 发布文章功能；
- 上传和选择封面图片；
- 兼容性和页面显示；
- 缺陷记录、回归和测试总结。

## 5-2 项目测试目标

1. 验证用户能否按照需求登录系统；
2. 验证手机号、验证码、滑块和协议等规则是否正确；
3. 验证文章标题、正文、封面、频道和提交方式是否符合需求；
4. 验证文章可以发表或保存为草稿；
5. 验证图片上传的格式、大小、批量上传和选择功能；
6. 验证不同浏览器下的布局和核心功能；
7. 发现缺陷并使用可复现、准确、完整的证据进行记录；
8. 根据用例执行情况给出是否具备继续测试或发布评估条件的结论。

## 5-3 测试对象与测试范围

### 登录模块

- 手机号输入和格式校验；
- 发送验证码；
- 滑块验证；
- 短信验证码输入；
- 用户协议勾选；
- 登录成功和失败提示；
- Chrome、Firefox、IE、Safari 等浏览器兼容性。

### 发布文章模块

- 文章标题；
- 文章正文；
- 封面类型和图片选择；
- 文章频道；
- 发表文章；
- 保存草稿；
- 文章内容的敏感字和安全输入风险。

### 上传图片模块

- 图片列表展示和分页；
- 图片选择状态；
- 单张上传和批量上传；
- JPG、PNG、GIF 格式；
- 2 MB 以内和超过 2 MB 的大小限制；
- 未选择图片时的异常提示。

# 二、Web 基础补充：HTML

课件在项目实战前补充了 HTML 基础。测试人员不一定需要成为前端开发人员，但了解常见 HTML 标签，有助于阅读页面结构、定位元素和理解页面显示问题。

## 5-4 前端三大技术

| 技术 | 主要职责 |
| --- | --- |
| HTML | 负责网页结构和内容 |
| CSS | 负责样式、布局和美化 |
| JavaScript | 负责交互行为和业务逻辑 |

## 5-5 常见 HTML 标签

| 标签 | 作用 |
| --- | --- |
| `<h1>` 到 `<h6>` | 标题，`h1` 的层级最高 |
| `<p>` | 段落 |
| `<a>` | 超链接，通过 `href` 指定地址 |
| `<img>` | 图片，通过 `src` 指定路径 |
| `<br>` | 换行 |
| `&nbsp;` | 空格 |
| `<div>` | 块级布局容器 |
| `<span>` | 行内容器，常用于局部样式 |
| `<ul>`、`<ol>`、`<li>` | 无序列表、有序列表和列表项 |
| `<form>` | 表单，承载用户输入和提交 |
| `<input>` | 输入框、密码框等表单控件 |

## 5-6 HTML 知识对测试的帮助

1. 页面布局错乱时，可以判断是结构、样式还是脚本问题；
2. 输入框、按钮和图片通常可以通过标签、属性或开发者工具定位；
3. 图片无法加载时，可以检查 `src`、网络请求和资源地址；
4. 超链接跳转异常时，可以检查 `href` 和打开方式；
5. 表单提交异常时，可以结合页面控件、请求参数和响应结果定位问题；
6. 发现 `img` 等标签内容被当成代码执行时，应进一步关注输入过滤和安全风险。

测试人员不需要只根据 HTML 结构判断缺陷原因。HTML 只能帮助定位，最终仍要结合需求、页面表现、Network、Console、接口和日志进行确认。

# 三、黑马头条登录功能测试

## 5-7 登录需求分析

### 5-7.1 手机号需求

1. 输入正确的中国手机号，要求为 11 位数字；
2. 手机号输入框失去焦点时进行校验；
3. 校验成功时显示成功状态；
4. 校验失败时显示失败状态，并提示手机号格式不正确；
5. 手机号正确时才允许继续发送验证码；
6. 未注册手机号、空手机号和格式错误手机号都属于需要重点验证的异常数据。

### 5-7.2 发送验证码和滑块需求

1. 点击发送验证码后进入滑块验证；
2. 滑块拖拽到指定位置时验证成功，并获取短信验证码；
3. 验证成功后，发送验证码按钮按需求消失或进入不可重复点击状态；
4. 滑块未拖拽到指定位置时，应有晃动提示；
5. 每次失败后滑块回到初始位置；
6. 失败达到 5 次时，仍应按规则提示并允许继续处理；
7. 第 6 次失败时，应提示“尝试过多，请点击重试”或系统规定的等价文案；
8. 点击重试后，滑块状态应恢复到可以重新验证的状态。

### 5-7.3 验证码需求

1. 输入正确验证码；
2. 输入错误验证码；
3. 验证码为空；
4. 验证码过期；
5. 验证码输入后与手机号、滑块状态一起参与登录校验。

### 5-7.4 用户协议需求

1. 勾选“我已阅读并同意”后可以继续登录；
2. 未勾选协议时点击登录，应提示用户勾选协议；
3. 正确手机号、正确验证码和已勾选协议同时满足时，登录成功并进入系统。

## 5-8 登录测试点

### 5-8.1 手机号测试点

| 分类 | 测试点 | 预期关注 |
| --- | --- | --- |
| 正向 | 已注册的 11 位数字手机号 | 校验成功，可以发送验证码 |
| 边界 | 10 位手机号 | 不能通过校验 |
| 边界 | 12 位手机号 | 不能通过校验 |
| 类型 | 11 位但包含字母 | 提示手机号格式不正确 |
| 类型 | 11 位但包含特殊字符 | 提示手机号格式不正确 |
| 业务 | 未注册手机号 | 按需求提示手机号不存在或不能登录 |
| 空值 | 手机号为空 | 不能发送验证码，给出明确提示 |
| 交互 | 输入后失去焦点 | 在规定时机触发校验，状态显示正确 |
| 输入 | 前后包含空格 | 按需求自动处理或提示格式错误 |
| 输入 | 超长粘贴 | 不能突破输入长度限制 |

### 5-8.2 验证码测试点

| 分类 | 测试点 | 预期关注 |
| --- | --- | --- |
| 正向 | 输入正确且未过期的验证码 | 可以继续登录 |
| 空值 | 不输入验证码 | 提示验证码不能为空 |
| 错误 | 输入错误验证码 | 提示验证码错误 |
| 过期 | 输入过期验证码 | 提示验证码已失效，需要重新获取 |
| 重复 | 重复使用旧验证码 | 不能绕过验证码校验 |
| 关联 | 更换手机号后使用旧验证码 | 不能错误登录另一个手机号 |

### 5-8.3 滑块测试点

| 分类 | 测试点 | 预期关注 |
| --- | --- | --- |
| 正向 | 一次拖拽到指定位置 | 验证成功，获取验证码，按钮状态正确 |
| 逆向 | 拖拽未到指定位置 | 晃动提醒，滑块回到初始位置 |
| 逆向 | 连续失败 5 次 | 每次都有提示，状态能够重新初始化 |
| 逆向 | 第 6 次失败 | 提示尝试过多并显示重试入口 |
| 恢复 | 点击重试 | 滑块恢复可操作状态 |
| 交互 | 快速拖拽、反向拖拽、拖拽后松手 | 页面无卡死、无异常跳转 |

### 5-8.4 协议和登录按钮测试点

1. 正确手机号、正确验证码、勾选协议，登录成功；
2. 正确手机号、正确验证码、未勾选协议，登录失败并提示勾选；
3. 错误手机号、正确验证码、勾选协议，登录失败；
4. 正确手机号、错误验证码、勾选协议，登录失败；
5. 所有输入为空时点击登录，按字段校验顺序给出提示；
6. 连续点击登录按钮，不应产生重复登录请求或异常页面；
7. 登录请求较慢时按钮状态、加载提示和重复提交控制正确；
8. 登录失败后用户输入和滑块状态符合需求，不能出现错误残留。

## 5-9 登录兼容性测试

课件测试点中列出了 Chrome、Firefox、IE 和 Safari 等浏览器。实际执行时应记录具体浏览器版本、操作系统、分辨率和网络条件。

| 浏览器 | 重点验证内容 |
| --- | --- |
| Chrome | 登录布局、输入校验、滑块、验证码和跳转 |
| Firefox | 表单交互、滑块拖拽、按钮状态和提示文案 |
| IE | 页面布局、图片文字显示、登录成功流程 |
| Safari | 页面布局、输入框行为、滑块和登录跳转 |

兼容性检查至少包括：

- 页面布局与原型是否一致；
- 图片、文字和按钮是否完整显示；
- 输入框能否正常输入和失去焦点；
- 滑块能否拖动并正确回到初始位置；
- 验证码和协议状态是否正常；
- 登录成功后能否正常跳转；
- 控制台是否出现浏览器特有报错。

# 四、黑马头条发布文章功能测试

## 5-10 发布文章需求分析

发布文章页面主要由标题、正文、封面、频道以及“发表”和“存草稿”等操作组成。测试时要先覆盖正常发表，再覆盖字段为空、格式不合法、封面选择错误和频道未选等异常场景。

## 5-11 文章标题测试点

### 正向测试

1. 标题为 5 个字符；
2. 标题超过 5 个字符；
3. 标题包含数字、字母、中文和常见特殊字符；
4. 标题前后包含空格时，按需求校验或处理；
5. 输入正常标题后可以发表或存草稿。

### 逆向测试

1. 标题为空；
2. 标题只有 4 个字符；
3. 标题长度不足时点击发表；
4. 标题输入超出允许长度；
5. 标题包含敏感字或黑名单词；
6. 标题包含脚本、HTML 标签或特殊编码，检查是否被当作代码执行；
7. 粘贴超长标题时，页面限制和错误提示正确。

课件用例中明确验证了标题至少为 5 个字符，因此应重点覆盖 4 个字符和 5 个字符两个边界点。

## 5-12 文章正文测试点

### 正向测试

1. 正文不为空；
2. 正文包含中文、英文、数字和常见特殊字符；
3. 正文内容正常保存并在文章结果中显示；
4. 正文较长时输入框、提交按钮和页面布局不异常；
5. 正文与标题、封面、频道组合后可以正常发表或存草稿。

### 逆向测试

1. 正文为空；
2. 正文只有空格或换行；
3. 正文包含敏感字；
4. 正文中输入 HTML 标签或 `<img src="...">` 等内容，检查是否被正确转义或过滤；
5. 粘贴超长正文，检查长度限制、页面性能和提交结果；
6. 正文中包含特殊符号时，保存后内容不能乱码或丢失。

## 5-13 封面测试点

发布文章支持以下封面方式：

1. 单图；
2. 三图；
3. 无图；
4. 自动选择。

### 单图

- 选择 1 张图片，发表成功；
- 选择单图但不选择图片，发表失败并提示选择封面图片；
- 单图模式选择多张图片时，应不能超过单图规则；
- 选择图片后取消选择，页面状态和提交校验正确。

### 三图

- 选择 1 张图片，按需求允许发表；
- 选择 2 张图片，发表成功；
- 选择 3 张图片，发表成功；
- 三图模式不选择图片，发表失败并提示选择封面图片；
- 尝试选择第 4 张图片，不能选择或给出明确限制提示；
- 取消其中一张图片后，选中状态和数量显示正确。

### 无图和自动

- 选择无图，满足其他字段要求时可以发表；
- 选择自动，系统按需求自动生成或选择封面；
- 发表结果中封面类型和实际封面状态一致；
- 存草稿时封面状态能够被保存，重新打开后不丢失。

## 5-14 频道测试点

1. 选择一个有效频道后可以发表；
2. 不选择频道时不能发表；
3. 频道为空时提示“文章发布的频道不可为空”或等价文案；
4. 频道列表显示正常，选中状态明确；
5. 选择频道后切换封面或编辑正文，频道状态不应被错误清空；
6. 保存草稿后重新打开，频道信息应符合保存结果。

## 5-15 发表和存草稿测试点

### 发表文章

文章标题、正文、封面和频道均满足要求时：

1. 点击发表后提交成功；
2. 页面跳转到文章待审核页面；
3. 文章标题、正文、封面和频道信息正确保存；
4. 发表按钮在请求处理中不能重复提交；
5. 网络异常或服务失败时提示明确，不能显示虚假的成功结果。

### 保存草稿

1. 输入合法标题、正文、封面和频道后点击存草稿；
2. 草稿保存成功后跳转到草稿箱；
3. 草稿状态与发表状态区分正确；
4. 重新打开草稿时，标题、正文、封面和频道信息不丢失；
5. 空标题、空正文等不满足规则的数据，按需求决定是否允许保存草稿，不能凭个人理解设置预期。

# 五、上传图片功能测试

## 5-16 图片上传需求

根据测试点和用例资料，图片上传重点验证：

- 图片格式支持 JPG、PNG、GIF；
- 图片大小限制为 2 MB 以内；
- 支持单张上传；
- 支持批量上传；
- 未选择图片时不能上传；
- 上传成功后可以在图片库中看到对应图片；
- 图片列表按照每页 10 张、分两行显示，超过 10 张时分页；
- 选择图片后显示绿色对号等选中标识。

## 5-17 图片上传测试点

### 格式

1. 上传 JPG 图片；
2. 上传 PNG 图片；
3. 上传 GIF 图片；
4. 上传不支持的格式，例如 BMP、TXT、PDF 或其他文件；
5. 修改文件扩展名但文件实际内容不是图片，检查服务端是否真正校验文件类型；
6. 大小写扩展名混合时，按需求确认是否支持。

### 大小

1. 上传小于 2 MB 的图片；
2. 上传正好 2 MB 的图片；
3. 上传大于 2 MB 的图片，例如 2.1 MB；
4. 选择多个图片时分别验证每张图片的大小；
5. 上传失败后文件列表、提示和页面状态正确。

### 数量和批量

1. 单张 JPG 图片上传成功；
2. 多张 JPG、PNG、GIF 图片批量上传成功；
3. 批量上传中混入不支持格式时，验证整体结果和失败提示；
4. 批量上传中混入超大图片时，验证合格图片是否上传、失败图片如何提示；
5. 快速重复点击上传按钮，不应重复上传同一文件；
6. 上传过程中刷新或离开页面，状态和结果符合需求。

### 图片选择和列表

1. “全部”和“收藏”列表可以正常打开；
2. 每页显示 10 张图片，按两行布局展示；
3. 图片超过 10 张时出现分页；
4. 点击图片后显示绿色对号；
5. 取消选择后绿色对号消失；
6. 切换“全部”和“收藏”时选择状态符合需求；
7. 图片缩略图、名称和加载状态显示正常；
8. 图片不存在或加载失败时有明确占位或错误处理。

## 5-18 图片上传用例示例

# 六、测试用例设计规范

## 5-19 什么是测试用例

测试用例是为测试项目而设计的执行文档。它不是简单记录“点一下按钮”，而是把测试条件、操作、数据和预期结果写成其他人可以重复执行的标准。

测试用例的作用：

1. 防止漏测；
2. 统一测试执行标准；
3. 方便多人协作；
4. 方便缺陷定位；
5. 方便回归测试；
6. 沉淀项目测试资产。

## 5-20 测试用例八大要素

| 要素 | 说明 |
| --- | --- |
| 用例编号 | 唯一标识，建议使用项目_模块_编号格式 |
| 用例标题 | 说明测试对象、条件和预期结果 |
| 项目/模块 | 说明属于哪个项目和功能模块 |
| 优先级 | 表示用例的重要程度，课程资料使用 P0 到 P4，P0 最高 |
| 前置条件 | 执行用例前必须准备的环境、账号、数据或页面状态 |
| 测试步骤 | 按顺序写出具体操作 |
| 测试数据 | 写明实际输入、文件、账号和配置 |
| 预期结果 | 写出页面、接口、数据和状态应该达到的结果 |

可以根据项目需要增加：

- 是否自动化；
- 是否冒烟用例；
- 执行人；
- 实际结果；
- 执行状态；
- 缺陷编号；
- 执行时间和环境。

## 5-21 用例标题写法

推荐格式：

```text
功能对象 + 条件/操作 + 预期结果
```

示例：

- 登录失败：手机号格式不正确；
- 发送验证码失败：滑块连续 6 次未验证成功；
- 发布文章成功：三图模式选择 3 张图片；
- 发布文章失败：标题少于 5 个字符；
- 上传图片失败：图片大小超过 2 MB。

标题应准确表达一个测试问题，避免使用“测试登录功能”“验证一下”等无法直接执行的模糊描述。

# 七、需求分析和测试点提取方法

## 5-24 个人实施流程

黑马头条项目可以按照以下顺序实施：

```text
熟悉模块需求
  -> 记录不明确的问题
  -> 与产品确认需求
  -> 分析功能规则
  -> 提取测试点
  -> 编写测试用例
  -> 用例评审
  -> 执行用例
  -> 提交和跟踪缺陷
  -> 回归验证
  -> 输出测试总结
```

## 5-25 测试点提取的三个覆盖方向

### 1. UI 原型覆盖

检查页面中是否存在需求规定的元素，并验证：

- 字段、按钮、勾选框、列表和提示是否完整；
- 文案、颜色、位置和状态是否符合原型；
- 页面在不同浏览器和分辨率下是否错位；
- 加载中、成功、失败、空数据和禁用状态是否有设计。

### 2. 规则覆盖

把需求中的限制词转换为测试数据和测试点：

- 必须、不能、为空、唯一；
- 至少、最多、超过、不足；
- 正确、错误、过期、未注册；
- 单个、多个、批量、重复；
- 发表、保存、取消、重试。

### 3. 兼容性覆盖

结合产品支持范围验证：

- Chrome、Firefox、IE、Safari 等浏览器；
- Windows、macOS、移动设备等系统或设备；
- 不同分辨率和缩放比例；
- 正常网络、弱网、延迟和请求失败；
- 不同账号状态、权限和数据量。

## 5-26 正向和逆向设计

### 正向测试

使用满足需求的数据，验证完整功能能否成功完成。例如：

- 已注册手机号、正确验证码、已勾选协议，登录成功；
- 合法标题、非空正文、有效频道和合法封面，文章发表成功；
- JPG、PNG、GIF 且不超过 2 MB 的图片上传成功。

### 逆向测试

使用不满足需求的数据或异常操作，验证系统是否拒绝错误请求并给出正确处理。例如：

- 手机号不是 11 位数字；
- 验证码错误或过期；
- 未勾选协议；
- 标题为空或少于 5 个字符；
- 正文为空；
- 三图模式选择 4 张图片；
- 图片大于 2 MB；
- 未选择图片就点击上传。

逆向测试不能只写“提示错误”。还要关注：

- 错误提示是否准确；
- 输入框是否正确标记；
- 页面是否停留在合理位置；
- 已填写内容是否保留；
- 是否发送了不应发送的请求；
- 是否产生脏数据或错误状态。

# 八、缺陷管理

## 5-27 什么是缺陷

软件在使用过程中存在的任何问题都可以称为软件缺陷，简称 Bug。

黑马头条项目中，以下情况都可能构成缺陷：

- 需求要求的功能没有实现；
- 实现结果与需求不一致；
- 多出需求没有规定的错误功能；
- 输入错误时没有正确提示；
- 文章或图片状态保存错误；
- 页面在支持的浏览器中布局错乱；
- 上传失败后数据状态不一致；
- 内容过滤不足导致 HTML 或脚本被执行；
- 页面、接口和文章状态显示不一致。

## 5-28 缺陷描述核心内容

一条完整缺陷至少应包含：

1. 缺陷标题；
2. 项目、模块和版本环境；
3. 缺陷类型；
4. 严重程度；
5. 优先级；
6. 前置条件；
7. 复现步骤；
8. 预期结果；
9. 实际结果；
10. 附件和证据；
11. 指派人和当前状态。

## 5-29 缺陷编写原则

### 可重现

别人按照步骤能够稳定复现，或者明确记录复现概率、账号、数据和环境差异。

### 唯一性

一条缺陷描述一个核心问题。多个独立问题应分别提交，避免开发无法判断修复范围。

### 准确

只描述实际观察到的现象，不把未经验证的原因当成事实。例如不要直接写“后端代码错误”，应写明请求、响应和页面实际表现。

### 具体

写明版本、浏览器、账号、数据、步骤、预期和实际结果，避免“不能用”“有问题”等模糊表达。

### 有证据

根据问题类型附上页面截图、录屏、Network、Console、接口响应、日志或数据库结果。上传前应脱敏密码、Token、手机号和其他敏感数据。

## 5-30 缺陷生命周期

```text
新建/提交
  -> 指派
  -> 开发修复
  -> 测试重测
  -> 关闭
```

如果重测仍然失败，应重新打开并补充最新证据。暂时不能修复的问题可以延期，但必须记录原因、影响、规避方式和计划版本。

常见状态包括：

- New：新建；
- Open：打开或处理中；
- Fixed：已修复，等待验证；
- Closed：验证通过并关闭；
- Reopened：回归失败，重新打开；
- Postponed：延期处理。

## 5-31 严重程度和优先级

课程资料中使用 S1 到 S4 表示严重程度，并使用 P0 到 P2 等优先级表示处理紧急程度。两者含义不同：

- **严重程度**：问题对功能、数据、用户和系统的影响有多大；
- **优先级**：问题需要多快处理。

例如，登录主流程完全不可用通常严重程度高、优先级也高；一个低概率但涉及内容安全的问题，严重程度和优先级也可能因项目风险而被提高。

## 5-32 黑马头条缺陷示例

```text
标题：三图模式选择 4 张图片后仍可以发表文章
模块：发布文章 / 封面
环境：测试环境，Chrome，Windows，版本以执行记录为准
严重程度：S2
优先级：P1
前置条件：登录成功，打开发布文章页面，素材库中存在 4 张可用图片。

复现步骤：
1. 输入合法文章标题。
2. 输入非空文章正文。
3. 选择三图封面模式。
4. 连续选择 4 张图片。
5. 选择有效频道并点击发表。

预期结果：三图模式最多选择 3 张图片，第 4 张不能选择，或页面明确提示已达到上限。
实际结果：第 4 张图片可以被选中，并且文章可以继续发表。

附件：页面录屏、图片选择状态截图、Network 请求信息。
```

# 九、测试执行、回归和测试报告

## 5-33 推荐执行顺序

```text
环境和账号确认
  -> 冒烟测试
  -> 登录核心流程
  -> 发布文章正常流程
  -> 登录和文章异常流程
  -> 图片上传专项
  -> 浏览器兼容性
  -> 缺陷重测
  -> 影响范围回归
  -> 测试总结
```

## 5-34 冒烟测试清单

- [ ] 登录页可以打开；
- [ ] 已注册手机号可以进行格式校验；
- [ ] 滑块验证可以成功完成；
- [ ] 正确验证码和协议勾选可以登录；
- [ ] 登录后可以进入运营平台；
- [ ] 发布文章页面可以打开；
- [ ] 合法标题、正文、封面和频道可以发表；
- [ ] 文章可以保存为草稿；
- [ ] 图片库可以打开并显示图片；
- [ ] 一张合法图片可以上传；
- [ ] Chrome 和至少一个项目要求的其他浏览器可以执行核心流程。

冒烟失败时，应先确认版本是否具备继续测试的条件，不要在核心页面不可用时直接执行大量详细用例。

## 5-35 缺陷重测与回归

### 重测

针对已修复的问题，按照原缺陷步骤重新验证。例如修复“标题为空仍可发表”后，重新执行空标题提交，确认提示和提交状态正确。

### 回归

根据修改影响范围检查相关功能。例如修复封面选择逻辑后，除了重测三图最多 3 张，还应回归：

- 单图选择 1 张；
- 三图选择 1、2、3 张；
- 三图不选图；
- 无图和自动封面；
- 发表文章和存草稿；
- 图片选择、取消选择和分页；
- 不同浏览器下的封面显示。

## 5-36 测试报告应包含的内容

1. 项目名称、版本和测试环境；
2. 测试范围和未覆盖范围；
3. 测试人员、执行时间和浏览器信息；
4. 用例设计数量、执行数量、通过数量、失败数量和阻塞数量；
5. 缺陷总数以及按严重程度、优先级、模块的分布；
6. 已修复缺陷的重测和回归情况；
7. 未解决缺陷、影响范围和规避方式；
8. 兼容性测试结果；
9. 发布建议或继续测试建议。

## 5-37 测试总结示例

```text
项目：黑马头条 Web 自媒体运营平台
测试范围：登录、发布文章、图片上传和浏览器兼容性
测试环境：测试环境，记录实际浏览器版本、操作系统和测试账号

执行情况：
- 登录正常、异常和滑块场景已执行；
- 发布文章标题、正文、封面、频道、发表和存草稿场景已执行；
- 图片格式、大小、单图、批量上传和图片选择已执行；
- 已对项目要求的浏览器完成核心流程验证。

主要风险：
1. 登录失败次数和滑块重试逻辑需要重点关注，避免验证码绕过或页面卡死；
2. 三图封面最多 3 张、单图未选择图片和频道为空属于高频校验点；
3. 文章正文中的 HTML 标签、敏感内容和脚本输入需要关注过滤和安全风险；
4. 图片超过 2 MB、批量上传部分失败和重复点击上传需要确认数据状态；
5. 修复封面、上传和登录逻辑后需要执行相关回归。

质量结论：
根据阻塞缺陷、严重缺陷、核心用例通过情况和未覆盖风险决定是否进入下一阶段。若登录主流程不可用、文章无法发表、图片上传造成数据异常或存在内容安全问题，不建议直接发布。
```

## 5-39 参考测试点

1. 标题为空；

4. 标题超过 5 个字符；
