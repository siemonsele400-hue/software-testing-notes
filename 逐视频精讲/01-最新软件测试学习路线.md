# 第 01 集：软件测试学习路线

> **本集定位**：课程导学与能力地图。它不是具体工具操作课，重点是回答“软件测试要学什么、先后顺序是什么、学到什么程度可以进入项目”。

## 一、课程原讲提炼

视频把课程分成三条主线：

1. **基础篇**：测试分类、测试流程、测试用例设计、测试计划和测试报告。
2. **进阶篇**：接口工具（JMeter、Postman）、Pytest、Requests、Selenium、自动化和性能测试。
3. **项目实战篇**：金融、银行、商城等项目，模拟企业从需求到发布的完整工作。

视频还强调了几项企业常用能力：Bug 管理、SVN/Git/GitHub 协作、Linux 服务器、数据库、接口测试、环境搭建以及项目经验。课程口播中的关注、点赞和资料领取不是学习指令；真正有用的是路线和能力要求。

## 二、为什么测试学习不能只学工具

测试工程师的工作对象不是某一个工具，而是一个持续变化的软件系统。工具只是执行手段：

- 不懂需求，JMeter 只能发请求，无法判断业务是否正确；
- 不懂 HTTP，Requests 脚本遇到 `401`、重定向或 Cookie 时无法定位；
- 不懂数据库，无法证明“页面成功”是否真的落库；
- 不懂测试设计，自动化只能重复少量正常路径；
- 不会写报告和表达，发现的问题也很难推动修复。

因此本课程应按“**测试思维 → 业务流程 → 用例设计 → 工具执行 → 数据与环境 → 自动化/性能 → 项目表达**”推进。

## 三、能力地图（把视频路线变成可验收目标）

### 1. 初级功能测试能力

你需要能够阅读需求规格说明书，区分功能和非功能要求；从注册、登录、搜索、下单等流程提取测试点；编写包含前置条件、步骤、预期结果和优先级的用例；执行用例、提交 Bug、验证修复并输出测试报告。

**验收作品**：一个登录/注册模块的测试点清单、20 条用例、3 条规范 Bug 和一页测试总结。

### 2. 中级测试能力

视频路线中提到 Linux、数据库和接口，这些能力的共同目的，是让测试人员可以穿透页面：

- 用 SQL 准备和校验数据；
- 用 Linux 命令查看日志、进程、端口和资源；
- 用 Postman/JMeter 验证接口、鉴权、关联和异常；
- 根据请求 ID 将页面、接口、日志、数据库结果串起来。

**验收作品**：一个接口集合、配套 SQL、一次日志排障记录和可复现的环境说明。

### 3. 自动化与质量工程能力

Requests/Pytest/Selenium/Jenkins 不是必须在第一天全部掌握。正确顺序是：

1. 先能手工判断正确性；
2. 再把稳定、重复、高频的检查自动化；
3. 加入数据隔离、断言、报告和失败排查；
4. 最后接入 CI，让每次代码变更都能得到反馈。

## 四、建议学习节奏

| 阶段 | 重点 | 可交付结果 |
|---|---|---|
| 第 1 阶段 | 测试分类、流程、需求分析 | 一张测试生命周期图 |
| 第 2 阶段 | 用例设计方法 | 登录、注册、三角形用例 |
| 第 3 阶段 | Bug、计划、报告、环境 | 一份测试计划和报告 |
| 第 4 阶段 | 金融项目 | 完整项目测试资产 |
| 第 5 阶段 | HTTP、SQL、Linux | 接口+数据库+日志排查 |
| 第 6 阶段 | JMeter、Requests、Pytest | 接口自动化项目 |
| 第 7 阶段 | Selenium、性能、CI | Web 自动化和性能报告 |

## 五、不要被“7 天精通”误导

课程标题是传播性表达。零基础学习者可以在几天内建立全貌，但真正达到可就业水平，必须通过反复练习形成证据：能写、能执行、能解释、能排查、能复盘。建议以“完成作品”而不是“看完视频”作为进度标准。

## 六、练习与答案

### 练习 1：路线排序

**题目**：为什么不建议刚学测试就直接学习 Selenium？

**答案**：Selenium 解决的是浏览器操作，不负责告诉你业务是否正确。若没有需求分析、用例设计和断言基础，容易只会点击页面，无法覆盖异常、权限、数据一致性和回归风险。

### 练习 2：能力证明

**题目**：面试官问“你会 JMeter 吗”，比单纯回答“会”更有价值的回答是什么？

**答案**：说明使用场景和产出，例如“我用 JMeter 调试登录和订单接口，使用 CSV 参数化、JSON 提取器做关联，用断言校验状态码和业务字段，并生成报告接入 Jenkins”。

## 七、面试高频问法

**问：功能测试、接口自动化和性能测试如何衔接？**

**答题思路**：功能测试先确认业务规则和核心路径；接口测试在更稳定的协议层验证数据和异常；自动化把高频回归固化；性能测试在业务正确的基础上评估响应时间、吞吐量和资源瓶颈。它们共享需求、数据和风险分析，不是互相独立的工具课程。

## 八、课后任务

画一张自己的学习地图，并为每个阶段写出一个可展示的作品。完成后再进入第 2 集，避免只记住工具名而不知道工具要解决什么问题。
