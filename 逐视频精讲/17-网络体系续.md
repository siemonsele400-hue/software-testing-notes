# 第 17 集：网络体系续——请求与响应分析

> **视频对应**：视频继续拆解 URL、Headers、Body、状态码、重定向、缓存、编码、Cookie、Token 和请求 ID，并把抓包思维用于接口测试。

## 1. 请求、响应与身份

URL 包含协议、域名、端口、路径和查询参数；Headers 传递身份、内容类型和追踪信息；Body 承载 JSON、表单或文件。响应要看状态码、Headers、Body、Cookie、耗时和 request ID。

Cookie 常由浏览器自动回传，Session 由服务端维护状态，Token 常放在 `Authorization` Header。测试缺失、过期、篡改、跨用户复用和退出后的失效。

## 2. 抓包示例

```bash
curl -i "https://api.test.local/v1/orders/1001" -H "Authorization: Bearer <脱敏token>" -H "X-Request-Id: test-20260909-001"
```

验证未带 Token 返回 401；过期/篡改不能访问；普通用户访问他人订单被拒绝；不存在订单符合 404/业务码契约；金额、状态和归属正确。对 302 要记录 `Location` 并检查每一跳；对缓存检查 `Cache-Control`、`ETag`/`304`；对编码验证中文和特殊字符。

## 3. 练习题与答案解析

### 练习 1

**题目**：登录拿到 Token，订单接口偶发 401，如何排查？

**参考答案**：核对提取路径、有效期、Header 名称、空格、账号隔离、环境及时钟；用 request ID 对比登录和鉴权日志，确认刷新时序。

**解析**：偶发 401 常由时序、过期、作用域或环境混用造成。

**验收标准**：覆盖 Token 内容、传递、生命周期、账号、时钟和日志。

### 练习 2

**题目**：接口返回 302，如何测？

**参考答案**：确认是否符合契约；记录 `Location`，分别测试不跟随和跟随后最终响应，检查登录失效、HTTP/HTTPS、缓存和循环跳转。

**解析**：自动跟随可能掩盖真实响应。

## 4. 面试问法与课后任务

**问：为什么不能只看页面？** 页面可能吞错误、缓存旧数据或误渲染成功；请求、响应、日志和数据库能定位层次。

**任务**：抓取登录→订单链路，脱敏保存摘要，标出 Cookie/Token、状态码、业务码和 request ID。
