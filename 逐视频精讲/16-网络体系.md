# 第 16 集：网络体系

> **视频对应**：视频从 DNS、连通性、端口、TCP/UDP、TLS 到 HTTP 状态码，建立分层定位网络问题的思维。

## 1. 关键概念

IP 标识主机，端口标识服务；DNS 把域名解析为 IP；TCP 面向连接、可靠有序，UDP 无连接、开销低；TLS 为 HTTPS 提供加密、完整性和证书身份；HTTP 负责请求/响应。

`2xx` 是协议层成功，`3xx` 常见重定向，`4xx` 多为请求/权限问题，`5xx` 多为服务端失败。`200` 不等于业务成功，还要检查 JSON 业务码、字段和状态。

## 2. 分层排查

1. `nslookup` 确认 DNS；2. `ping` 或路由工具确认基础连通；3. 检查端口、防火墙；4. 验证 TCP/TLS、证书和协议；5. 用 Postman/curl 看 HTTP；6. 用 request ID 关联应用和下游日志。

## 3. 练习题与答案解析

### 练习 1

**题目**：HTTP 200 但页面显示余额查询失败，查什么？

**参考答案**：响应 JSON 业务码、前端解析、request ID 对应日志、数据库余额和账号状态。

**解析**：HTTP 层成功不代表业务层成功。

**验收标准**：覆盖协议、业务、前端、日志和数据五层。

### 练习 2

**题目**：DNS 解析到旧 IP，如何区分缓存和配置问题？

**参考答案**：比较本机 DNS 与公共/权威结果，清理缓存，检查 hosts、代理和 TTL，再确认新 IP 服务状态。

**解析**：区分本机缓存、递归 DNS、权威记录和服务端。

## 4. 面试问法与课后任务

**问：TCP/UDP 对测试有什么影响？** TCP 关注连接、重传、超时和有序；UDP 关注丢包、乱序和应用层补偿。

**任务**：为一个接口画 DNS→端口→TLS→HTTP→日志排查图，每层写命令或证据。
