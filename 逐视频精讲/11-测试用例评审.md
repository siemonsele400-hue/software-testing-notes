# 第11集：测试用例评审

> **类型**：逐视频精讲  
> **主题**：用例质量门禁  
> **内容层级**：课程主线、基础补充、企业实战、就业重点

## 1. 本集学习目标

本集结束后，你应能解释“用例质量门禁”是什么、为什么重要、什么时候使用、如何转成测试活动，并能独立完成至少一个业务练习。学习标准不是看完视频，而是能留下可执行用例、执行证据、Bug、SQL、脚本或报告。

## 2. 逐视频精讲：核心知识

用例评审是执行前的质量门禁，不是走形式的朗读会议。评审要检查需求追踪、业务流程、正常/异常/边界、权限、数据、环境、预期可判定性和优先级。产品确认业务规则，开发确认实现边界，测试负责覆盖和风险说明。会议输出必须有问题编号、责任人、截止时间、版本和未决事项。

### 2.1 从需求到测试动作

拿到本集对应的业务需求后，按以下顺序处理：

1. 识别角色、对象、状态和业务目标。
2. 找出输入约束、组合条件、边界、异常和不可逆操作。
3. 确定前置数据、环境、权限和依赖服务。
4. 把规则写成操作步骤和可观察预期。
5. 同时验证页面/接口、数据库、日志、消息和状态。
6. 按业务影响确定优先级和回归范围。

### 2.2 课程知识与补充知识的连接

课程中的方法是入口，企业测试还要回答三个问题：  
- **证据在哪里？** 页面提示之外，是否有接口、数据库和日志证据。  
- **失败如何恢复？** 超时、重试、回滚、刷新、后退或第三方失败后状态是否正确。  
- **问题如何交付？** 是否能提交可复现 Bug、说明影响并在修复后完成回归。

## 3. 详细实操示例

以“用户注册并进入登录”作为示例：

- 有效数据：满足长度、字符集和唯一性规则的用户名。
- 无效数据：空值、超长、非法字符、已注册用户名、密码不一致。
- 流程验证：注册成功 -> 登录成功 -> 首页展示账号信息。
- 恢复验证：注册接口超时、重复点击、刷新、关闭弹窗后重新进入。
- 数据验证：用户表只有一条记录，密码不可明文，默认状态和角色正确。
- 证据记录：版本、账号、时间、请求 ID、响应、数据库查询和截图。

## 4. 企业实战补充

- 核心业务、资金、权限、隐私、数据一致性和不可逆操作优先。
- 无效用例尽量一次只引入一个主要错误原因。
- 测试数据可准备、可清理、可重复；并行执行使用独立账号和唯一前缀。
- 需求有歧义时记录问题、影响和临时假设，确认后更新追踪关系。
- 测试、压测、安全验证和数据库操作必须在授权环境执行。

## 5. 常见错误与排查

| 错误 | 改进 |
| --- | --- |
| 只会复述定义 | 用新业务重写测试点和用例 |
| 只测成功路径 | 增加边界、异常、重试和恢复 |
| 只看页面提示 | 同步验证接口、数据库、日志和状态 |
| 失败没有证据 | 保存版本、时间、请求ID和数据条件 |
| 用例之间互相污染 | 设计前置、清理和独立数据 |
| 测试完成就建议发布 | 结合缺陷、覆盖和遗留风险判断 |

## 6. 本集练习题

### 练习 1：本集方法迁移

**题目**：请把“用例质量门禁”应用到一个登录、订单或借贷需求中，写出至少 8 个测试点。

**答案与解析**：至少应包含一个主成功路径、两个业务规则验证、两个边界/异常、一个权限或数据一致性验证、一个重复/超时/恢复场景和一个可观测证据点。只写页面文字而不写业务状态，说明覆盖仍不完整。

### 练习 2：优先级判断

**题目**：如果时间只够执行 20% 的用例，先执行哪些？

**答案与解析**：先执行启动、登录、核心查询/创建、支付/审核等主链路，再执行资金、权限、数据一致性、不可逆操作和高频历史缺陷。优先级表示先测什么，不等于严重程度。

## 7. 面试高频题

### 问：你如何证明自己掌握本集内容？

**参考回答**：我能以一个具体业务为例，从需求拆解、风险识别、方法选择、数据准备、步骤预期、证据保存、Bug 提交到回归结论完整说明，而不是只背诵概念或工具名称。

### 问：发现需求不明确怎么办？

**参考回答**：记录具体歧义、影响范围和临时假设，在需求评审中与产品和开发确认；确认后更新需求、测试点、用例和报告口径，避免个人猜测成为测试标准。

## 8. 课后输出

- 一页本集知识卡片。
- 8～15 个测试点或用例。
- 至少 1 条异常/边界/恢复场景。
- 一段 150 字项目化复盘。
