# 第 04 集：项目测试需求分析

> **本集重点**：需求分析解决“测什么”。视频把测试需求定义为依据需求规格说明书，识别业务流程、功能需求、非功能需求和具体测试点，并以登录/注册页面示范拆分方法。

## 一、测试需求与测试点的区别

测试需求是需要验证的总体要求，例如“用户可以注册并登录”。测试点是把要求拆成可检查的风险单元，例如手机号格式、验证码有效期、重复注册、密码规则、登录失败次数和登录后权限。

测试点不是简单把页面上的每个按钮抄一遍，而是回答：在什么条件下，用户做什么，系统状态应如何变化，失败时如何反馈，数据和权限是否正确。

## 二、先画业务流程，再列功能

以课程中的登录/注册思路为例：

```text
进入登录页
  ├─ 输入已有账号和正确密码 → 登录成功 → 首页
  ├─ 输入错误密码 → 错误提示 → 仍在登录页
  ├─ 点击注册 → 注册页 → 提交注册 → 登录页/首页
  └─ 忘记密码 → 验证身份 → 设置新密码 → 返回登录
```

流程图帮助识别分支、回退、异常和状态，而需求文档通常只描述主流程。没有流程图时，测试人员应根据文字、原型和接口关系自行补画，并让产品确认。

## 三、功能需求与非功能需求

### 功能需求

描述系统做什么：注册账号、登录、搜索商品、提交订单、支付和确认收货。分析时关注输入、处理、输出、状态变化、角色和关联功能。

### 非功能需求

视频提到界面、兼容性、易用性、性能和安全。补充理解如下：

- **界面**：文字、布局、控件状态、错误提示和响应式显示；
- **兼容性**：浏览器、操作系统、设备、分辨率和网络；
- **易用性**：用户是否容易理解、学习和完成任务；
- **性能**：响应时间、并发、吞吐量、资源和稳定性；
- **安全**：认证、授权、会话、输入校验和敏感信息保护。

分析实物时也可沿用这个思路。比如测纸杯，功能是装水；非功能包括容量、耐热、易用、安全和抗压。面试中的“随手测试一个杯子”本质上考察这种思维迁移。

## 四、登录页面的测试点拆解

### 账号字段

空值、前后空格、最短/最长长度、非法字符、大小写、未注册账号、已注销账号、超长输入和复制粘贴。还要验证前端限制与后端限制是否一致，绕过前端直接请求接口是否仍校验。

### 密码字段

必填、错误密码、大小写、复杂度、错误次数锁定、密码是否明文展示、浏览器自动填充、修改密码后旧密码失效。

### 验证码与会话

验证码为空、错误、过期、重复使用、刷新后旧验证码是否失效；登录成功后 Token/Cookie 是否生成，退出后是否失效，未登录访问首页是否被拦截。

### 业务结果

成功进入首页、用户身份正确、权限菜单正确、登录日志记录正确；失败时提示准确且不泄露“账号存在与否”等敏感信息。

## 五、覆盖率不是越大越好

需求覆盖率应说明已识别的需求是否有测试点和用例；用例执行率说明计划用例中实际执行的比例。两者都 100% 仍可能漏掉未写进需求的风险，因此还要进行探索性测试、历史缺陷回归和风险评估。

## 六、练习与答案

### 练习 1：从需求提取测试点

**题目**：需求“注册成功后自动登录并跳转首页”，至少列出 8 个测试点。

**答案**：正常注册、重复账号、密码规则、验证码、网络中断、注册成功但自动登录失败、首页权限、刷新/后退、数据库用户记录、重复点击提交。答案应覆盖主流程、异常、状态和数据。

### 练习 2：非功能识别

**题目**：电商搜索功能除了关键词正确性，还应分析什么？

**答案**：空关键词、特殊字符、超长词、大小写、无结果展示、分页排序、响应时间、并发、权限、缓存旧数据、不同浏览器和网络。

## 七、面试高频问法

**问：你拿到一份没有流程图的需求怎么做？**

**答**：先识别角色、入口、主流程、分支、异常、状态和外部依赖，画出流程图并标注待确认项；再按功能和非功能维度形成测试点，邀请产品确认后编写用例。

## 八、课后任务

为登录和注册各写一张测试点表，列出“测试点、输入/条件、预期、风险等级、来源需求”，并标出哪些点需要接口、数据库或日志协助验证。

### 课后任务参考答案

| 测试点 | 输入/条件 | 预期 | 风险 | 验证手段 |
|---|---|---|---|---|
| 注册成功 | 未注册手机号、合法密码 | 创建用户并提示成功 | 高 | 页面+接口+SQL |
| 重复注册 | 已存在手机号 | 拒绝创建且提示明确 | 高 | 接口+SQL |
| 验证码过期 | 使用过期验证码 | 拒绝提交，数据库无新用户 | 高 | 页面+日志+SQL |
| 登录失败锁定 | 连续输错达到阈值 | 账号进入锁定状态 | 高 | 接口+用户状态 |
| Token 失效 | 退出后重放旧 Token | 返回未认证，不能访问首页 | 高 | 接口+日志 |
| 空密码 | 账号正确，密码为空 | 前端阻止或后端返回参数错误 | 中 | 页面+接口 |

解析：来源需求用于追溯，风险等级用于排优先级，验证手段用于决定是否需要超越页面观察。测试点应描述可验证行为，不应只写“检查登录功能”。
