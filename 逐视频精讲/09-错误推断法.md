# 第09集：错误推断法

> 类型：逐视频精讲 + 教材式补充 + 实操与就业
> 本集主题：从历史缺陷、用户习惯和开发常见错误主动猜测风险。

## 1. 学习目标

本集不是只记“从历史缺陷、用户习惯和开发常见错误主动猜测风险。”的定义，而是要能把它应用到一个新业务，形成测试点、用例、执行证据、Bug 或报告。

## 2. 逐视频精讲

课程主线：空值、重复提交、并发、超时、刷新、后退、权限、缓存、编码、金额和第三方失败。

教材解释：测试活动必须明确对象、输入、前置条件、动作、预期和证据。需求、用例、执行和报告之间要保持可追溯关系，不能把页面提示直接当成业务成功。

## 3. 实操步骤

1. 确认版本、环境、账号、数据和测试范围。
2. 阅读需求、原型、流程或接口文档，记录歧义和假设。
3. 应用本集方法设计成功、异常、边界、恢复和权限场景。
4. 执行并保存请求、响应、截图、日志、SQL、流水号或状态。
5. 修复后先验证原问题，再按影响范围回归。
6. 更新用例、缺陷、报告和风险清单。

## 4. 企业实战补充

- 核心业务、资金、权限、隐私、数据一致性和不可逆操作优先。
- 测试数据要可准备、可清理、可重复，并支持并行隔离。
- 无效用例尽量一次只引入一个主要错误因素。
- 需求有歧义时记录问题、影响和临时假设，确认后更新追踪关系。
- 测试、压测、安全验证和数据库操作必须在授权环境完成。

## 5. 常见错误

- 只背定义，不知道什么时候使用。
- 只测成功路径，不测边界、重复、超时和恢复。
- 只看页面，不验证接口、数据库、日志或状态。
- 测试失败没有版本、时间、请求ID和数据条件。
- 把执行完成误写成没有质量风险。

## 6. 练习题与答案解析

### 练习 1：方法迁移

题目：请把“从历史缺陷、用户习惯和开发常见错误主动猜测风险。”应用到登录、订单或借贷需求中，至少写出 8 个测试点。

答案：至少包含主成功路径、业务规则、边界/异常、权限或数据一致性、重复/超时/恢复和证据点。

解析：能把方法迁移到新业务，才说明真正理解；只写页面文字而不写业务状态，覆盖仍不完整。

### 练习 2：优先级

题目：时间只够执行 20% 用例时先测什么？

答案：先测启动、登录、核心查询/创建、支付/审核、资金、权限、数据一致性、不可逆操作和历史高风险缺陷。

解析：优先级表示先测什么，不等于严重程度；发布判断还要结合遗留风险。

## 7. 面试高频题

问：你如何证明自己掌握本集内容？

参考回答：我能用具体业务说明需求拆解、方法选择、数据准备、步骤预期、证据保存、Bug 提交和回归结果，而不是只背概念或工具名称。

## 8. 课后输出

- 8～15 个测试点或用例。
- 至少 1 个异常、边界或恢复场景。
- 一段 150 字项目化复盘。

## 11. 深入讲解：错误推断法的证据来源

错误推断法不是没有依据地猜测，而是把以下信息转成风险假设：

| 证据来源 | 可推断的风险 |
| --- | --- |
| 历史 Bug | 同一模块是否再次出现回归 |
| 相似系统 | 当前实现是否遗漏行业常见边界 |
| 需求歧义 | 产品、开发和测试理解是否不一致 |
| 用户行为 | 连点、刷新、后退、复制粘贴、异常中断 |
| 技术实现 | 缓存、异步消息、事务、编码、时区和并发 |
| 线上数据 | 峰值、空数据、脏数据、超长数据和重放 |

每条推断都要写成可验证的假设，例如：“支付接口超时后，用户再次点击支付，系统可能创建第二笔订单”。对应的测试应明确超时时间、重复动作、订单数量、流水数量、扣款次数和最终状态。

## 12. 详细案例：支付超时与重复提交

### 12.1 业务规则

- 一个订单只能对应一次有效支付结果。
- 客户端超时不代表服务端没有收到请求。
- 同一支付流水重复回调必须幂等。
- 支付失败应允许业务规定范围内重试。

### 12.2 测试设计

1. 正常支付成功，验证订单、支付流水、库存和通知。
2. 客户端超时但服务端成功，刷新页面后只能看到一笔订单。
3. 支付请求重复发送，验证幂等键和流水唯一性。
4. 支付回调重复发送，验证不会重复扣款或重复发货。
5. 支付失败后重试，验证旧订单状态和新流水关系。
6. 网络恢复前后重复点击，验证前端按钮状态和服务端幂等。

### 12.3 证据要求

记录请求时间、请求 ID、幂等键、订单号、支付流水、响应、服务端日志和数据库结果。仅凭页面显示“支付处理中”不能判定系统正确。

## 13. 错误推断清单

- 空字符串、全空格、前后空格和不可见字符。
- 长度刚好达到边界、超过数据库字段长度或超过网关限制。
- 重复点击、重复提交、重复回调和并发创建。
- 刷新、后退、关闭页面、重新登录和多标签页操作。
- token 过期、权限变化、账号禁用和会话失效。
- 时区切换、月末、闰年、夏令时和跨天任务。
- 缓存旧值、异步延迟、消息重复和消息丢失。
- 大小写、Unicode、全角半角、编码和特殊字符。
- 数据库为空、脏数据、孤儿记录和唯一键冲突。
- 第三方接口慢、失败、返回空响应或返回格式变化。

## 14. 练习题与答案解析

### 练习 5：导入功能

**题目**：批量导入用户时，除了验证“正常 Excel 导入成功”，还应推断哪些风险？

**答案**：空文件、超大文件、重复用户、缺少必填列、列顺序变化、非法字符、超长字段、部分成功、重复导入、恶意文件、编码错误和导入中断恢复。

**解析**：错误推断要从文件、数据、事务、权限和恢复多个角度展开。批量导入最容易出现“页面提示失败但部分数据已写入”的一致性问题。

### 练习 6：风险排序

**题目**：以下风险应优先验证哪三个：按钮颜色不一致、支付重复扣款、列表空数据显示异常、普通用户越权查看他人订单？

**答案**：支付重复扣款、越权查看他人订单、空数据异常。

**解析**：资金和隐私权限影响最大；空数据异常可能影响功能可用性；按钮颜色问题通常可后置，但仍应记录。

## 15. 面试回答升级

### 问：错误推断法和探索性测试有什么区别？

**参考回答**：错误推断法是根据历史缺陷、经验和技术风险提出有针对性的错误假设，再设计验证；探索性测试强调在较少预设脚本下边学习、边设计、边执行。两者都依赖测试人员判断，但错误推断更聚焦“可能出错的地方”，探索性测试范围更开放。

### 问：如何避免错误推断变成随意测试？

**参考回答**：给每条推断记录证据来源、风险描述、验证步骤、预期结果和优先级；执行后将有效推断沉淀为回归用例，将无效推断记录为已验证假设。
