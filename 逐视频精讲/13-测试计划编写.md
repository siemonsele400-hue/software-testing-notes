# 第 13 集：测试计划编写

> **视频对应**：视频讲解测试计划要回答“测什么、怎么测、谁来测、何时测、何时结束”，并覆盖范围、策略、资源、排期、环境、数据、进入/退出标准、风险和交付物。

## 1. 测试计划不是排班表

测试计划是项目级约定，连接需求、测试执行和发布决策。它先界定范围：本轮验证哪些功能、接口、平台和版本；再说明策略：使用哪些测试类型、方法和工具；最后写清谁在什么环境、什么时间完成什么交付物。

## 2. 视频主线拆解

### 范围与目标

以“注册+登录+订单”为例，目标不是笼统的“保证质量”，而是验证核心流程、权限、数据一致性、异常恢复和兼容性风险。

### 资源与环境

写明测试人员、产品/开发接口人、浏览器或设备、数据库、第三方沙箱、账号角色和数据准备方式。环境依赖没有写清，计划无法执行。

### 进入与退出标准

进入标准可以是需求和原型已确认、构建可安装、冒烟通过、测试数据准备完成。退出标准应包含用例执行率、关键需求覆盖、阻塞 Bug、严重缺陷和遗留风险，而不是只写“测试完成”。

### 风险与应对

例如支付依赖第三方沙箱不稳定，就准备模拟回调；数据迁移时间不足，就安排回滚演练；需求频繁变更，就保留影响分析和回归缓冲。

## 3. 示例计划

| 项目项 | 本轮约定 |
| --- | --- |
| 版本/范围 | v1.4 注册、登录、下单、取消订单；不含退款 |
| 测试策略 | 冒烟→功能→接口→回归；高风险场景优先 |
| 环境 | staging，Chrome/Edge，MySQL 脱敏库，支付沙箱 |
| 排期 | 需求确认 1 天、设计 1 天、执行 3 天、回归 1 天 |
| 进入标准 | 构建可部署、核心接口可用、数据脚本通过 |
| 退出标准 | 高优先级用例 100% 执行；阻断/致命 Bug 为 0；遗留风险获批准 |
| 交付物 | 用例、缺陷清单、测试报告、风险清单 |

计划中的数字必须来自实际项目约束。不能把“100%覆盖”当成永远适用的口号；对未覆盖项应说明原因和补测安排。

## 4. 练习题与答案解析

### 练习 1

**题目**：为“校园缴费”功能写出 5 项测试计划内容。

**参考答案**：范围含缴费、撤销和账单查询；策略含功能、接口、兼容性和异常恢复；资源含测试账号、支付沙箱和数据库；退出标准含核心用例执行率、资金类缺陷门槛和遗留风险审批；风险含回调延迟、重复扣款和对账。

**解析**：计划要覆盖决策所需信息，不能只列测试步骤。

**验收标准**：至少包含范围、策略、资源、标准和风险五类，且每类可执行。

### 练习 2

**题目**：测试环境每天 18:00 重置数据，计划如何调整？

**参考答案**：把数据准备和清理安排在重置窗口前后，关键用例使用可重复脚本；执行记录写明数据批次；跨天场景使用独立账号或固定时钟，并在计划中增加环境不可用风险。

**解析**：环境限制会直接影响排期、数据和结果可信度，不能留到执行时才发现。

## 5. 面试问法与课后任务

**问：进入标准和退出标准有什么区别？** 进入标准判断是否具备开始测试的条件，退出标准判断是否达到阶段完成和发布决策条件；二者都应可度量、可追踪。

**任务**：为一个登录+订单小版本写一页测试计划，至少包含范围、策略、资源、排期、进入/退出标准、风险和交付物。
