# 前置课程 02：HTTP 与网络基础

## 1. 学习目标

理解浏览器或 JMeter 发出的请求如何到达服务端，并能独立分析 URL、方法、状态码、请求头、Cookie、Token、响应体和超时。接口测试、Web 自动化、性能测试都依赖这套语言。

## 2. 一次请求发生了什么

用户输入 `https://example.com/api/users?page=1` 后，客户端通常经历：DNS 将域名解析为 IP，建立 TCP 连接，HTTPS 再进行 TLS 握手，发送 HTTP 请求，服务端经过网关、应用和数据库处理后返回响应。测试定位问题时要判断失败发生在哪一层：解析失败、连接失败、TLS 失败、HTTP 业务失败还是数据落库失败。

## 3. HTTP 报文结构

```http
POST /api/login HTTP/1.1
Host: api.example.com
Content-Type: application/json
Authorization: Bearer <token>

{"username":"alice","password":"secret"}
```

请求由方法、路径、协议版本、请求头和请求体组成。响应由状态行、响应头和响应体组成。`Content-Type` 描述发送或返回的数据格式；不能只看状态码，还要校验业务码、字段类型和副作用。

## 4. 常见方法与状态码

- `GET` 查询资源，通常不应产生副作用。
- `POST` 创建资源或执行动作。
- `PUT` 整体更新，`PATCH` 局部更新。
- `DELETE` 删除资源。
- `2xx` 表示协议层成功，`400` 请求参数错误，`401` 未认证，`403` 无权限，`404` 资源不存在，`409` 冲突，`429` 限流，`5xx` 服务端或依赖故障。

状态码是协议层信号，不等于业务成功。例如支付受理可能返回 `200` 但业务状态为“处理中”。

## 5. Cookie、Session、Token

Cookie 通常由浏览器保存并自动随域名发送；Session 状态保存在服务端，Cookie 只携带会话标识；Token 通常由客户端显式放入 `Authorization`。测试要覆盖：未登录、Token 过期、Token 被篡改、账号退出后旧 Token 是否失效、普通用户访问管理员资源是否返回 `403`。

## 6. JSON 与接口校验

```json
{
  "code": 0,
  "message": "ok",
  "data": {"id": 101, "items": []}
}
```

校验分四层：HTTP 状态码；响应头和格式；业务码与消息；字段存在性、类型、范围、关联关系。列表为空时应验证是否返回 `[]` 而不是 `null`，分页字段是否仍完整。

## 7. 幂等、重试和超时

网络超时不代表服务端没有处理请求。创建订单、支付、扣款等动作应使用幂等键或业务唯一号。测试步骤：发送请求并人为制造客户端超时，使用相同幂等键重试，检查订单数、流水数、扣款次数和最终状态。重试策略要区分连接失败、`429`、临时 `5xx` 和明确业务拒绝。

## 8. 常用排查命令

```powershell
nslookup example.com
ping example.com
Test-NetConnection example.com -Port 443
curl.exe -i https://example.com/health
```

`ping` 被禁用并不代表 HTTP 不通；应结合 `Test-NetConnection`、`curl`、浏览器 Network 和服务端日志判断。不要把生产敏感 Token 粘贴到公共命令记录中。

## 9. 接口测试清单

必测：必填/选填、类型、长度、边界、非法枚举、特殊字符、空值、重复提交、权限、分页、排序、并发、超时、依赖失败、错误消息和数据一致性。每条用例都保存请求、响应、环境、账号、时间和关联 ID。

## 10. 练习与答案

**练习 1：** `/users` 未登录返回 `401`，登录但无权限返回 `403`，两者有什么区别？

**答案：** `401` 表示身份认证缺失或无效，客户端需登录或刷新凭证；`403` 表示身份已识别但不允许访问，重试登录通常不能解决。

**练习 2：** POST 超时后如何判断是否重复创建？

**答案：** 使用同一业务请求号重试，查询服务端日志和数据库唯一键，核对资源数量、状态和下游消息；不能只看客户端一次超时。

## 11. 面试表达

问：接口测试为什么要验证数据库？

答：接口响应正确不代表事务完整。对创建、更新、扣款等操作，我会核对关键表、状态流转、唯一性和关联数据，确认没有“页面成功但数据未落库”或重复写入。

## 12. 课后输出

用 `curl` 调一个公开的本地测试服务，整理一张请求/响应字段表，并写出至少 12 条异常和权限用例。
