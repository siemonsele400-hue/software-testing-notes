# 前置课程 04：Linux 零基础（测试排障）

## 1. 学习目标

能登录测试服务器、查看目录和进程、检查端口、搜索日志、分析磁盘与内存，并形成“现象—证据—结论”的排障记录。性能测试、接口测试和线上问题复现都会用到。

## 2. 文件与目录

```bash
pwd
ls -lah
cd /var/log
mkdir -p ~/test-data
cp app.log ~/test-data/
```

Linux 路径使用 `/`，`~` 表示当前用户家目录。相对路径依赖当前目录，排障记录中尽量使用绝对路径，避免“我本地能看到、同事找不到”。

## 3. 查看和搜索日志

```bash
tail -n 100 app.log
tail -f app.log
grep -n "ERROR\\|Timeout" app.log
grep -R "request_id=abc123" /opt/app/logs
less app.log
```

先按时间范围和请求 ID 缩小范围，再看上下文。`tail -f` 适合观察实时复现；不要把整份含敏感信息的日志复制到公共聊天中。

## 4. 进程、端口与网络

```bash
ps -ef | grep java
top
free -h
df -h
ss -lntp
curl -i http://127.0.0.1:8080/health
```

进程存在不代表服务健康；端口监听不代表业务可用。应继续检查健康接口、依赖连接、错误日志和资源指标。`df -h` 看磁盘空间，`free -h` 看内存，必要时结合 `iostat`、`vmstat`。

## 5. 权限与退出码

```bash
whoami
ls -l app.log
chmod u+x run.sh
./run.sh
echo $?
```

退出码 `0` 通常表示成功，非零表示失败；脚本中应让失败正确返回，避免 CI 误报成功。不要为了方便直接使用 `chmod 777` 或 `sudo`，先确认最小权限。

## 6. 测试排障流程

1. 记录环境、版本、时间、账号和请求 ID。
2. 检查 DNS、端口、进程和健康检查。
3. 对照应用日志、网关日志和数据库日志。
4. 检查资源、依赖超时、连接池和磁盘。
5. 复现后保存命令、输出、日志片段和结论。

## 7. 常见错误

- 在错误服务器或错误环境执行命令。
- 只看最后一行日志，忽略完整堆栈和请求上下文。
- 用 `grep error` 漏掉大小写、结构化字段或 trace ID。
- 直接删除日志、重启服务，导致证据丢失。

## 8. 练习与答案

**练习 1：** 接口返回 502，先查什么？

**答案：** 先确认请求时间和网关日志，再检查后端端口、进程、健康检查及连接超时；502 通常说明网关无法获得有效上游响应，但最终需证据确认。

**练习 2：** 如何持续观察某个请求？

**答案：** `tail -f app.log | grep --line-buffered 'request_id=...'`，复现后按 `Ctrl+C` 退出，并保存关键上下文。

## 9. 面试表达

问：你如何定位接口偶发超时？

答：我先按请求 ID 和时间对齐客户端、网关、应用和数据库日志，再看 CPU、内存、连接池、线程池和下游耗时，区分网络、应用、数据库或依赖瓶颈，并保留复现证据。

## 10. 课后输出

在本地 Linux/WSL 创建一个模拟日志，完成一次“搜索错误—定位请求—统计错误数量—写出结论”的排障记录。
