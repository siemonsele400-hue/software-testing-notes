# 前置课程 06：命令行与测试环境搭建

## 1. 学习目标

掌握 Windows PowerShell 的目录、文件、环境变量、进程和端口操作；理解“系统环境、项目环境、测试环境”的区别；能建立可复现的 Python 测试项目。

## 2. 认识命令行

命令行是通过文本命令操作系统。提示符前的路径是当前工作目录，命令通常由“程序 + 参数 + 选项”组成。例如 `python -m pytest -q` 中，`python` 是程序，`-m pytest` 运行模块，`-q` 控制输出。

## 3. PowerShell 常用命令

```powershell
Get-Location
Get-ChildItem -Force
Set-Location C:\path\to\project
New-Item -ItemType Directory tests
Copy-Item source.txt target.txt
Get-Content app.log -Tail 100
Get-Process
Get-NetTCPConnection -LocalPort 8080
```

含空格或中文的路径使用引号并优先加 `-LiteralPath`。删除或移动前先用 `Resolve-Path` 核对绝对路径，不在不明确的位置执行递归删除。

## 4. PATH 和环境变量

PATH 是系统查找可执行程序的目录列表。安装 Python 后命令找不到，通常是终端未刷新、PATH 未配置，或电脑存在多个 Python。

```powershell
Get-Command python
where.exe python
$env:TEST_BASE_URL = "http://127.0.0.1:8000"
```

环境变量适合保存环境地址和运行参数；密码应交给专门的凭证管理，不应写进源码和截图。

## 5. 可复现项目搭建

```powershell
mkdir software-testing-lab
cd software-testing-lab
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install requests pytest
python -m pip freeze > requirements.txt
mkdir tests
```

创建 `tests/test_smoke.py`：

```python
def test_environment_ready():
    assert 1 + 1 == 2
```

运行：

```powershell
python -m pytest -q
```

使用 `python -m pytest` 能确保 pytest 来自当前 Python 环境，减少“安装在 A 环境、运行在 B 环境”的问题。

## 6. 测试环境分层

- 开发环境：开发快速验证，变化频繁。
- 测试环境：功能和接口测试，数据相对可控。
- 预发布环境：配置尽量接近生产，用于发布前验证。
- 生产环境：真实用户环境，只进行获批的低风险验证。

环境记录应包含版本、部署时间、配置、数据库、依赖地址、测试账号和已知限制。不要用“测试环境坏了”代替证据。

## 7. 环境问题排查顺序

1. 确认命令、当前目录和配置文件。
2. 确认解释器、虚拟环境和依赖版本。
3. 确认环境变量、代理、证书和网络。
4. 确认服务进程、端口、健康检查和日志。
5. 用最小用例复现，比较正常环境与异常环境差异。

## 8. 常见错误

- 直接双击脚本，错误窗口一闪而过。
- 在错误目录运行，读取了另一份配置或测试数据。
- 没激活虚拟环境，依赖装到全局。
- 用生产账号和真实数据练习。
- 修改配置后未记录，导致问题不可复现。

## 9. 练习与答案

**练习 1：** `pytest` 提示不是命令，但已经安装怎么办？

**答案：** 激活项目虚拟环境，执行 `python -m pip show pytest` 和 `python -m pytest`；再检查 `Get-Command python` 是否指向 `.venv`。

**练习 2：** 同一脚本同事能跑、你不能跑，怎么比较？

**答案：** 对比代码提交、Python 和依赖版本、环境变量、配置、测试数据、网络代理和服务地址，并用最小用例逐层排除。

## 10. 面试表达

问：如何保证自动化测试可以在不同机器运行？

答：依赖通过 `requirements.txt` 固定，配置与代码分离，敏感项由环境变量或 CI 凭证注入；README 写清初始化和运行命令，测试数据可构造和清理，并在 CI 中持续验证。

## 11. 课后输出

从空目录创建一个可运行的 Pytest 项目，写明安装、激活、执行和排错步骤；在新终端按 README 重建一次，确认不是“只在当前机器碰巧可用”。
